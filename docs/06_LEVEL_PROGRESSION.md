# 《冰箱清空计划》8 关难度曲线与规则编排 v0.4

## 1. 本文档地位

本文档定义比赛版 8 个首发关卡的正式难度曲线、教学顺序、主要资源冲突、特殊规则与三星条件。

它建立在：

- `00_PROJECT_CHARTER.md`
- `01_GAME_DESIGN_SPEC.md`
- `02_UI_UX_SPEC.md`
- `03_DAY1_VERTICAL_SLICE.md`
- `04_CONTENT_CATALOG.md`

之上。

若后续实现与本文档冲突，涉及关卡节奏、关卡目标和关卡库存时，以本文档较新的关卡编排为准；DAY 1 的交互细节仍以 `03_DAY1_VERTICAL_SLICE.md` 为最高优先级。

---

## 2. 关卡设计总原则

8 关不能只是“换一批食材”。

每关必须至少满足一个条件：

1. 教一个新约束；
2. 对已经学会的约束做一次更复杂的组合；
3. 引入新的资源冲突；
4. 让玩家发现此前形成的习惯并不总是最优。

比赛版只有四类核心规则：

- 保质期 / 即期食材；
- 总烹饪时间；
- 总份数；
- 总热量。

其他条件，例如“至少做 3 道菜”，只能作为轻量目标或三星条件，不发展成第五套独立系统。

全程不设置现实倒计时。

所有特殊约束都是“游戏内预算”。玩家可以超出预算继续做菜，但会失去对应目标/三星，不出现硬失败。

---

## 3. 重要规则修订：不要把游戏做成猜菜谱

正式关卡中，玩家打开“今晚还能做”时，应直接看到当前关卡相关菜谱：

- 菜名；
- 所需食材；
- 份数；
- 烹饪时间；
- 若存在热量规则，则显示热量。

不要因为“菜谱图鉴未解锁”而把正在玩的 Puzzle 变成 `???` 猜配方。

菜谱图鉴的收集逻辑改为：

- `seen`：玩家在关卡里见过该菜谱；
- `cooked`：玩家真正做过该菜谱；
- 只有 `cooked` 才解锁完整菜品插画与图鉴卡。

核心挑战始终是资源分配，而不是测试玩家现实做饭知识。

- 西兰花炒虾仁：8 分钟；

- 菠菜鸡蛋汤：6。

- 已用 8 分钟；
- 剩 7 分钟；
- 番茄鸡蛋面需要 8 分钟。

玩家仍然可以继续做，但顶部预算变为 16/15，并失去时间目标。

`⏱ 0 / 15 分钟`

READY 菜谱出现时，显示预览：

`+8 → 8/15`

若会超预算：

`+8 → 16/15`

使用橙/红提示，但仍允许“开火”。

## 7. 三星

- ★：完成今晚；
- ★★：处理至少 2/3 即期单位；
- ★★★：即期 3/3，且总时间 ≤15。

# DAY 4 — 两个人的晚餐

## 1. 新规则

首次引入：

**总份数目标。**

剧情：

> 今天不是给自己随便对付一口，至少准备 4 份食物。

教学重点：

> 做了 3 道菜，不一定比做了 2 道菜更够吃。

## 2. 库存

- 鸡胸肉 ×2【今天处理】
- 生菜 ×1【今天处理】
- 蘑菇 ×1
- 洋葱 ×1
- 土豆 ×1
- 胡萝卜 ×1
- 玉米 ×1
- 豆腐 ×1
- 番茄 ×1
- 黄瓜 ×1

## 3. 可涉及菜谱

- 洋葱蘑菇鸡肉：2 份；
- 鸡肉玉米沙拉：2 份；
- 土豆鸡肉煲：3 份；
- 番茄豆腐汤：1 份；
- 黄瓜拌豆腐：1 份。

## 4. 关键结构

因为生菜只能通过鸡肉玉米沙拉处理，所以优秀路线通常先锁定：

- 鸡肉玉米沙拉。

另一份鸡胸肉可选择：

- 洋葱蘑菇鸡肉 → 总计 4 份；
- 土豆鸡肉煲 → 总计 5 份。

因此首次允许多个明显不同的三星解。

## 5. UI

顶部：

`👥 0 / 4 份`

READY 菜谱显示：

`+2 份`

烹饪完成后份数累加。

## 6. 三星

- ★：完成今晚；
- ★★：总份数 ≥4；
- ★★★：总份数 ≥4，且即期食材全部处理。

## 3. 关键菜谱

- 鸡蛋黄瓜三明治：420 kcal；
- 芝士香肠吐司：560 kcal；
- 苹果酸奶杯：190 kcal；
- 芝士煎蛋：260 kcal。

## 4. 三星方案

- 鸡肉玉米沙拉：320；
- 鸡蛋黄瓜三明治：420；
- 苹果酸奶杯：190。

- 芝士香肠吐司：560；

`560 + 320 + 190 = 1070 kcal`

仍然可以把食材清完，但会超过目标。

玩家第一次真正体验：

> 同样处理掉吐司，不同做法有不同代价。

## 6. UI

顶部：

`🔥 0 / 1000 kcal`

READY 菜显示：

`+420 kcal`

若会超标则预览变为橙/红。

## 7. 三星

- ★：完成今晚；
- ★★：即期食材全部处理；
- ★★★：即期食材全部处理，且 ≤1000 kcal。

这能形成一个很清晰的 2 星学习结果：

“我清空了，但选的做法太高热量。”

```text
玉米虾仁炒蛋
+8 分钟   +2 份   +330 kcal
```

顶部目标在玩家尚未开火前显示 ghost preview：

```text
⏱ 30 → 38 / 40
👥 5 → 7 / 7
🔥 850 → 1180 / 1250
```

若某项超标，只将该项变为警示色。

不弹确认框。

不阻止玩家开火。

这能让失败仍然属于玩家的选择，而不是 UI 偷偷替玩家做决定。

---

## 6. “今晚还能做”的三态升级

DAY 1–2：

- 可以做；
- 现在做不了。

DAY 3 以后增加第三态：

### 可以做

库存满足，且不会违反当前预算。

### 可以做，但会超目标

库存满足，但如果现在做，会让时间 / 热量等超过目标。

显示黄色或橙色预算标记，例如：

`会超时 +1 分钟`

### 现在做不了

库存不足。

三者必须区分。

“会超目标”不是“做不了”。

## 7. 关卡节奏曲线

### DAY 1–2：理解选择

玩家关注：

- 谁在抢同一个食材？

### DAY 3–4：理解约束

玩家开始同时关注：

- 食材；
- 时间或份数。

### DAY 5：第一次全局规划

玩家应该开始在第一次开火前停顿几秒。

### DAY 6：理解“同一目标有不同成本”

不是所有能清食材的菜都等价。

### DAY 7：识别隐藏关键资源

稀缺辅料也能决定整局。

### DAY 8：综合规划

玩家需要同时看：

- 即期；
- 鸡蛋数量；
- 时间；
- 份数；
- 热量。

但因为所有变化都通过 READY 预览展示，所以信息复杂度仍可控。

---

## 8. 难度设计禁区

后续不得用以下方法制造难度：

- 隐藏关键规则；
- 用现实冷门菜谱知识卡玩家；
- 加大量食材让玩家找不到东西；
- 缩小点击区域；
- 加现实倒计时逼玩家误触；
- 随机改变配方；
- 让同一个输入随机产出不同菜；
- 用“错误”“失败”弹窗惩罚探索；
- 要求背诵之前关卡配方。

真正允许提高难度的方式只有：

- 更多资源竞争；
- 更紧的预算；
- 多个合理方案之间的取舍；
- 约束组合。

## 9. 开发实现建议

关卡规则必须数据驱动。

建议：

```ts
interface LevelConstraints {
  maxCookTime?: number
  minServings?: number
  maxCalories?: number
}

interface LevelConfig {
  id: string
  title: string
  inventory: Record<string, number>
  urgent: Record<string, number>
  constraints: LevelConstraints
  starRules: StarRule[]
}
```

运行时统一维护：

```ts
cookTimeUsed
servingsMade
caloriesMade
urgentUsed
```

不要分别为 DAY 3 / DAY 4 / DAY 6 写专属逻辑。

## 10. 最终内容 Gate

开发顺序仍然保持：

1. DAY 1 Vertical Slice；
2. 验证“做错后愿意重玩”；
3. 实现通用约束框架；
4. DAY 2–4；
5. DAY 5–6；
6. DAY 7–8；
7. 最后统一做数值与文案压测。

在 DAY 1 核心体验没有通过之前，不允许因为“8 关文档已经写完”而直接批量生产全部关卡。

## 11. 8 关体验完成后的目标认知

玩家打完 DAY 8 后应该形成以下思考习惯：

> 先看今天必须处理什么。
>
> 再看哪些食材被多道菜争抢。
>
> 然后看时间、份数和热量预算。
>
> 最后才决定第一道菜做什么。

如果玩家开始在点击“开火”之前主动停顿和规划，《冰箱清空计划》的核心玩法就已经从“菜谱组合器”成立为真正的轻策略 Puzzle。
