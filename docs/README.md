## 文档优先关系

- DAY 1 的具体交互、状态机和核心教学：以 `03_DAY1_VERTICAL_SLICE.md` 为准。
- DAY 2–8 的正式关卡库存、教学顺序、特殊约束和三星条件：以 `06_LEVEL_PROGRESSION.md` 为准。
- `04_CONTENT_CATALOG.md` 是基础内容池，不覆盖 `06_LEVEL_PROGRESSION.md` 的较新关卡编排。
- 当前实际完成度与可试玩入口：以 `08_IMPLEMENTATION_STATUS.md` 和 `../game/` 为准。

## 当前项目状态

**初版游戏 v0.1 已完成。**

稳定试玩入口：`../game/play.html`。

当前版本已经实现 8 个关卡、25 种食材、20 道菜以及四类核心规则。后续工作应优先做真实用户试玩、反馈调参和正式美术替换，而不是继续扩大系统范围。

## Canonical 核心

DAY 1 必须保持：

- 4 道菜都争抢鸡蛋；
- 只有 3 个鸡蛋；
- 最优方案放弃洋葱煎蛋；
- 玩家不能被教程直接告知最优解；
- 最后一个鸡蛋消耗后必须反馈其他选择被关闭；
- 非 100% 结算必须明确告诉玩家剩余即期食材。

全游戏必须保持：

- 核心难度来自资源竞争与预算约束，而不是猜菜谱；
- 不设置现实时间倒计时；
- 特殊预算允许超出，但超出只影响目标 / 三星，不硬失败；
- 下一关不以三星为解锁门槛。

## 修改规则

设计变化不要只改代码。

若用户明确批准修改核心规则，应同步更新对应设计文档，避免代码和 AI 上下文漂移。
