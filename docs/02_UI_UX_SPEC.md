# 02 — UI / UX 与交互规范

## 1. 总体原则

目标设备：手机竖屏。

参考设计尺寸：`390 × 844`。

UI 必须服务于四个即时问题：

1. 什么东西今天必须处理？
2. 冰箱里还有什么？
3. 我现在准备做什么？
4. 做完以后还有多少选择？

任何新增 UI 若不能帮助上述问题，应谨慎加入。

## 2. 主要页面

比赛版只保留：

- P01 首页。
- P02 关卡选择。
- P03 主游戏页。
- P04 “今晚还能做”底部抽屉。
- P05 结算 / 分享卡。
- 菜谱图鉴可作为次级页面，但不应抢开发优先级。

不做账号中心、商城、签到、排行榜、任务中心等。

## 3. 首页

首页本身表现为关闭的冰箱，而不是普通菜单列表。

核心内容：

- 游戏名：《冰箱清空计划》。
- 冰箱门便签：当前 DAY + 关卡名。
- 唯一高强调主按钮：`继续挑战`。
- 次级入口：`关卡 / 菜谱 / 报告`。

点击继续挑战后：

- 冰箱门打开。
- 冷白光亮起。
- 约 0.5 秒进入主游戏页。

## 4. 主游戏页结构

参考纵向结构：

```text
┌────────────────────────┐
│ DAY / 关卡名       结束 │
│ 今天必须处理            │
│ 即期食材图标与数量       │
├────────────────────────┤
│                        │
│       冰箱内部          │
│                        │
├────────────────────────┤
│ 今晚菜单  N 道          │
├────────────────────────┤
│ 今晚还能做 X 道菜  ＞   │
├────────────────────────┤
│ [槽1][槽2][槽3][槽4]    │
│       料理锅            │
│ 清空              开火！ │
└────────────────────────┘
```

最大面积必须给冰箱和食材。

## 5. 顶部目标区

仅显示本关最重要目标。

基础示例：

```text
今天必须处理
番茄×2  米饭×1  牛奶×1
```

后期可增加最多一条特殊目标：

- `👥 2 / 6 人份`
- `🔥 420 / 750 kcal`
- `⏱ 8 / 15 分钟`

同屏不要超过两个目标条。

## 6. 冰箱视觉

采用正面打开的内部视角，不用夸张斜透视。

建议层级：

- 上层：牛奶、酸奶、饮品。
- 中层：鸡蛋、豆腐、熟食。
- 保鲜层：剩饭、午餐肉、保鲜盒。
- 蔬菜抽屉：番茄、胡萝卜、菠菜等。

不要把所有食材排成整齐 App 网格；应像真实冰箱随手摆放，但仍保持可识别和可点击。

## 7. 食材状态

每个食材最多突出三件事：

- 食材本体。
- 数量。
- 保质状态。

`urgent` 使用小型红色纸贴“今天”。

`soon` 使用轻黄色标签。

不要让整个食材闪红光。

数量尽量同时用视觉数量与 `×N` 表示，例如三个鸡蛋真的画三个。

## 8. 操作方式

食材必须同时支持：

### 拖拽

长按/拖入料理区，提供明显游戏感。

### 点击

轻点后以短动画自动飞入料理槽，解决长距离拖拽不便。

两种操作无需切换模式。

## 9. 拿起与预扣

拿起：

- 约 100ms 后食材放大约 108%。
- 产生轻微阴影。
- 原位置保留淡色占位。
- 料理区亮起可放置反馈。

放入料理区后：

- 只预扣，不正式消耗。
- 对应库存单位变成约 40% 透明。
- 点击料理槽、拖回冰箱或点击“清空”可撤回。

## 10. 料理槽

固定 4 个单位槽。

例如番茄炒蛋表现为：

```text
[番茄][番茄][鸡蛋][空]
```

不是 `[番茄×2][鸡蛋]`。

这样能强化真实资源单位的消耗感。

若四槽已满，再点击第五个食材：

- 不加入。
- 料理区轻震。
- 短提示：`锅里放不下更多了。`

## 11. 料理区四态

### EMPTY

`放点什么进去试试。`

开火禁用。

### POSSIBLE

当前选择是某些菜谱的子集。

`好像能做点什么……`

### READY

完整匹配菜谱。

显示菜名，`开火！` 高亮。

### INVALID

不属于任何菜谱子集。

`这几样好像不太搭。`

轻微震动，不消耗食材。

## 12. 提示强度

不能把游戏变成照答案配菜。

当 POSSIBLE 且玩家约 2 秒无操作：

- 若只有一个合理缺失食材，可显示其灰色轮廓。
- 若有多个候选，不给具体答案。

例如只放入鸡蛋时，可显示一次：

> 鸡蛋很百搭，再想想？

绝不能显示：

> 鸡蛋只有三个，请合理分配。

## 13. “今晚还能做”

这是核心常驻组件。

格式：

`今晚还能做 X 道菜 ＞`

数字随库存实时变化。

当关键食材耗尽并关闭其他方案时，必须额外短提示：

```text
鸡蛋用完了
1 道菜暂时做不了了
```

避免“错误选择”字样。

## 14. 菜谱 Bottom Sheet

点击“今晚还能做”后，自底部弹出，约占 60–65% 高度。

结构：

```text
今晚还能做

可以做
- 番茄炒蛋
- 蛋炒饭
- 牛奶蒸蛋

──────────
现在做不了
- 洋葱煎蛋   鸡蛋 0/1
```

点击某道菜不要自动制作，只高亮对应冰箱食材。

DAY 1 可以公开四道菜名；DAY 2 起再逐步增加图鉴探索。

## 15. 开火动画

总时长目标约 0.8 秒：

- 0–0.2s：食材聚向锅中央。
- 0.2–0.45s：锅轻晃、蒸汽。
- 0.45–0.7s：锅盖/短光效。
- 0.7–0.8s：成品出现、恢复输入。

不要做数秒真实烹饪动画。

## 16. 今晚菜单

冰箱与料理区之间放一条很窄的横向区域：

`今晚菜单 2 道 [番茄炒蛋] [蛋炒饭]`

最多显示 3 个缩略图，更多时横滑。

点击成品可查看菜名、人份、热量、游戏内烹饪时间。

## 17. 任务完成反馈

处理完某个即期目标后：

- 图标短暂缩小。
- 打勾。
- 从顶部目标中消失。

当所有即期食材处理完成：

`✓ 今天要救的东西都处理好了`

Header 右侧 `结束` 变为高强调 `完成今晚`。

不要自动跳结算。

## 18. 提前结束

如果还有即期食材，点击结束弹 Bottom Sheet：

```text
今晚还有东西没处理

牛奶 ×1

现在结束，它会被算作浪费。

[再看看] [就这样吧]
```

不要使用“确认退出”。

## 19. 结算页

不要使用健康 App 常见的大圆环仪表盘。

优先使用大数字：

```text
100%
冰箱清空率
```

同时展示：

- 浪费金额。
- 菜品数量。
- 营养等级。
- 三星。
- 剩余即期食材。
- 冰箱人格。
- 今晚 MVP。

主按钮随结果变化：

- 100%：`下一关`
- 非 100%：优先 `重新规划`

## 20. 分享结果卡

单独生成 3:4 卡片，不直接截图整个 UI。

推荐信息层级：

```text
冰箱清空计划
DAY X / 关卡名

98%

我是「极限清库存型」

做出 4 道菜
浪费 ¥1.20
今晚 MVP：鸡蛋

一句人格文案

你的冰箱里没有剩菜，
只有还没被想出来的晚饭。
```

不堆二维码，不做广告海报式排版。

## 21. 美术语言

- 场景：低饱和、略暗的生活化厨房。
- 冰箱：冷白偏蓝光。
- 食材：相对更饱和、辨识度高。
- 红：仅表示即期/浪费风险。
- 黄：仅表示快不新鲜。
- 主 UI 不以绿色为主，避免健康产品感。

食材使用统一的轻写实 2.5D 游戏插画，不混用不同风格照片。

## 22. 字号层级参考

- 大结果数字/人格：32–40。
- 关卡名：20–24。
- 菜名/按钮：15–17。
- 辅助信息：12–13。

避免主游戏页堆 10px 小字。

## 23. 音效最小集

- 冰箱门打开。
- 拿起食材。
- 食材落槽。
- 无效组合。
- 开火。
- 菜品完成“叮”。
- 100% 结算。

BGM 非 DAY 1 核心验收项。

## 24. 状态机建议

```text
LEVEL_INIT
→ PLAYING
→ INGREDIENT_SELECTED / RECIPE_MATCHING
→ RECIPE_READY
→ COOKING
→ PLAYING
→ LEVEL_FINISH
→ RESULT
```

仅在 `COOKING`（约 0.8 秒）和结果转场中短暂锁操作。
